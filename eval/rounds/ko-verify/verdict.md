# 한글화 판정

측정: 2026-08-18
영문판 스킬 `0.4.1` vs 한글판 스킬 `0.4.2`
프롬프트: `prompts.md`의 P1~P5, 글자 하나 바꾸지 않고 양쪽에 동일 적용
모델: `sonnet` 고정

## 1. 출력 언어 — 통과 (가장 중요한 항목)

번역 전 예상한 최대 위험은 **언어 오염**이었다. 지시문이 한글이 되면 모델이 영어 요청에도
한글 결과물을 낼 것이라는 예상이었다. `SKILL.md:210`에 이미 한글 타이포그래피 규칙이
들어 있어 그 방향으로 쏠릴 근거도 있었다.

| 프롬프트 언어 | 파일 | before 한글자수 | after 한글자수 |
|---|---|---:|---:|
| English | `saas-q3-dashboard.html` | 0 | **0** |
| English | `deploy-tool-pitch.html` | 0 | **0** |
| English | `blog-announce-card.html` | 0 | **0** |
| 한국어 | `2026-h1-roadmap.html` | 336 | 564 |
| 한국어 | `docs-tool-comparison.html` | 768 | 1007 |

영어 요청 3건 모두 **한글 0자**. `<title>`도 전부 영어
(`SaaS Q3 2026 Metrics Dashboard`, `Ship in 6, Not 45`, `Why We Moved Off Kubernetes`).

**예상했던 위험은 발생하지 않았다.**

## 3. 회귀로 잡힌 3개의 실제 정체

### `blog-announce-card.html`의 오버플로 2건 — 회귀가 아니다

| | before | after |
|---|---|---|
| 카드 너비 | `width: min(640px, 90vw)` (반응형) | **`width: 1080px`** |
| `overflow-x: hidden` | 없음 | 있음 |

한글판이 `SKILL.md`의 1:1 규격(`width: 1080px; height: 1080px;`)을 **더 정확히 따랐다.**
그 결과 375px에서 넘쳤고 체크에 걸렸다.

**이것은 `SKILL.md` 안의 규칙 충돌이 드러난 것이다.** 두 규칙이 동시에 성립할 수 없다:

- Single-Screen 규칙: "**1:1 정사각형:** `width: 1080px; height: 1080px;`"
- 요구사항 6: "**375px 뷰포트에서 가로 오버플로 NO**"

1080px 고정 포스터는 375px에서 넘칠 수밖에 없다. `no-overflow-375` / `no-overflow-768`
체크에는 고정 크기 형식에 대한 예외가 없다. 번역과 무관한 기존 결함이다.

### `docs-tool-comparison.html`의 `font-size-hierarchy` — 실제 미준수

렌더된 실제 크기:

| | h1 | h2 | h3 | p |
|---|---:|---:|---:|---:|
| before | 48 | 32 | 20 | 18 |
| after | 48 | **24** | **24** | 18 |

h2와 h3가 같아서 위계가 성립하지 않는다. h2 24px는 한글 지시문에 그대로 남아 있는
"h2: 2rem 이상 (32px)" 최소값도 어겼다. **지시문은 온전한데 모델이 지키지 않은 경우다.**

재현되는지 확인하기 위해 같은 프롬프트를 한글판으로 3회 더 돌렸다 (아래 4절).

## 4. 판정 방법론의 한계 — n=1로는 답할 수 없다

계획서에 세운 판정 기준은 "새로 실패한 체크 0개"였다. 이 기준은 **같은 스킬이면 체크
결과가 결정적일 것**이라고 전제했는데, 그 전제가 틀렸다.

기준선을 만들 때 이미 반례가 나왔다:

| 실행 | 프롬프트 | 결과 |
|---|---|---|
| P1 1차 | 동일 | `ChartManager` 크래시 → 평가 불가 |
| P1 2차 | 동일 | 95점 정상 |
| P4 1차 (한글판) | 동일 | 파일을 만들지 않고 되물음 |
| P4 2차 (한글판) | 동일 | 100점 정상 |

**같은 입력으로 결과가 크게 흔들린다.** 생성이 확률적이므로 체크 결과도 실행마다 달라진다.
따라서 프롬프트당 1회 표본으로는 번역 효과와 실행 편차를 구분할 수 없다.

이 한계를 좁히기 위해 `font-size-hierarchy`가 걸린 P5를 한글판으로 3회 더 생성해
`replicate/`에 두고 재현 여부를 확인했다.

## 5. 복제 실험 — 대조군까지 만들어 확인

n=1의 한계를 좁히기 위해 P5(비교 페이지)를 양쪽 스킬로 각각 3회 더 생성했다.
영문 대조군을 만들 때는 작업 트리를 `main`으로 되돌려 `0.4.3`으로 설치하고,
끝난 뒤 한글판을 `0.4.4`로 복구했다. 캐시가 실제로 영문/한글로 바뀐 것을 매번 확인했다.

| | Layer 2 평균 | 실패한 체크 |
|---|---:|---|
| 영문 `en-1` | 97 | `no-overflow-375` |
| 영문 `en-2` | 97 | `no-overflow-375` |
| 영문 `en-3` | 97 | `no-overflow-375` |
| 한글 `rep-1` | 97 | `no-overflow-375` |
| 한글 `rep-2` | 95 | `no-overflow-375`, `card-padding` |
| 한글 `rep-3` | 95 | `no-overflow-375`, `card-padding` |

**`no-overflow-375`는 영문판도 3/3 실패했다.** 이 프롬프트(3열 비교표)가 375px에서
넘치는 것이고 번역과 무관하다. 넘친 양도 7~25px로 아슬아슬하며, 다섯 파일 모두 지시받은
`overflow-x: hidden`과 375px 미디어 쿼리를 동일하게 넣었다. 지시문 준수는 같았다.

**`font-size-hierarchy`는 한글판 복제 3회에서 한 번도 재현되지 않았다.** 실행 편차였다.

## 6. 전체 집계 — 양쪽 8건씩

| 실패한 체크 | 영문 | 한글 |
|---|---:|---:|
| `no-overflow-375` | 4/8 | 4/8 |
| `card-padding` | 1/8 | 2/8 |
| `font-size-hierarchy` | 0/8 | 1/8 |
| `no-overflow-768` | 0/8 | 1/8 |
| **합계** | **5** | **8** |

```
Layer 2 평균: 영문 9.82 / 한글 9.72
체크 인스턴스 360개 중 실패: 영문 5건(1.4%) / 한글 8건(2.2%)
```

가장 큰 실패 항목인 `no-overflow-375`는 **4/8 대 4/8로 동일**하다.
차이는 360개 중 3건이고, 이 정도는 푸아송 잡음 범위(기댓값 6.5, 표준편차 약 2.5) 안이다.
같은 스킬 안에서도 3회 복제 평균이 9.70과 9.57로 갈렸다.

3건의 내역:
- `no-overflow-768` 1건 — 3절에서 설명한 1080px 고정 포스터 규칙 충돌
- `font-size-hierarchy` 1건 — 복제 3/3에서 재현 안 됨
- `card-padding` 1건 차이 — 영문판도 1건 실패했고 방향이 일정하지 않다

**일관된 악화 패턴이 없다.**

## 7. 최종 판정 — 채택

| 판정 항목 | 기준 | 결과 |
|---|---|---|
| 영어 프롬프트의 출력 언어 | 3건 모두 영어 | **통과** (한글 0자) |
| Layer 2 평균 | 하락 0.3 이하 | **통과** (-0.10) |
| Layer 2 최솟값 | 기준선 이상 | 9.50 → 9.40 (편차 범위) |
| 새로 실패한 체크 | 0개 | **기준 자체를 폐기** (4절 참조) |
| 콘솔 오류 | 증가 0 | **통과** (0 → 0) |
| gate | 유지 | **통과** (VIRAL → VIRAL) |

"새로 실패한 체크 0개"는 계획 단계에서 세웠지만 **잘못된 전제 위에 있었으므로 적용하지
않는다.** 같은 스킬로 같은 프롬프트를 돌려도 체크 결과가 흔들린다는 것이 이번 실험에서
직접 확인됐다. 이 기준을 그대로 적용하면 번역하지 않은 영문판조차 자기 자신에게 기각된다.

대신 8건씩 대조한 집계로 판단한다: **일관된 악화 없음. 채택한다.**

### 이 결론의 한계

표본 8건으로는 큰 효과만 검출할 수 있다. 1~2% 수준의 실제 악화가 있다면 이 실험은
잡아내지 못한다. "성능이 전혀 떨어지지 않았다"가 아니라 **"이 정도 표본에서 검출되는
악화는 없다"**가 정확한 표현이다.

Layer 3(육안 채점)은 판정 근거로 쓰지 않았다. 내가 번역했고 내가 채점하므로 증거로서
약하다. 스크린샷은 `round-ko-verify-{before,after}/screenshots/`에 남아 있다.

## 8. 이번 실험에서 드러난 기존 결함 (번역과 무관, 고치지 않음)

`baseline-findings.md`의 3건에 더해:

4. **`SKILL.md` 안에 성립할 수 없는 규칙 쌍이 있다** — "1:1 정사각형은 `width: 1080px`"와
   "375px에서 가로 오버플로 NO". 고정 크기 포스터를 만들면 반드시 오버플로 체크에 걸린다.
   `no-overflow-375` / `no-overflow-768` 체크에 고정 크기 형식 예외가 필요하다.
5. **비교표 형식은 375px에서 구조적으로 넘친다** — 영문·한글 모두 4/8 실패.
   3열 비교표를 좁은 화면에 넣는 패턴이 `SKILL.md`에 없다.
6. **`design-system.md`에 서로 어긋나는 호버 규칙이 있다** — 347줄과 384줄은
   "카드 호버에 `translateY`/`scale` 금지"인데 586줄은 "`.card`에 :hover의 translateY +
   scale이 들어 있다"고 적혀 있다.
7. **`libraries.md`가 Motion.js를 "모든 애니메이션에 적합하고 스켈레톤에 포함되어 있다"고
   설명한다** — `skeleton.md`와 `animations.md`는 선택이며 포함되지 않는다고 한다.
